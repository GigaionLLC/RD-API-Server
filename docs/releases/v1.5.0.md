# RD-API-Server v1.5.0

**Release date:** 2026-08-17

**Status:** Minor release. Console improvements and a scope-visibility fix; no breaking changes, no
migration, no configuration change.

---

## Pickers search instead of listing

A fleet is thousands of devices. A directory-synced deployment has as many user groups as the
directory does. Rendering either into a `<select>` builds every row into the DOM on page load, so
the page is slowest for exactly the deployments with the most to manage — and the operator can only
scroll it, never search for the name they already know.

Device and user pickers already worked this way. This release brings the rest into line:

| Picker | Was | Now |
|---|---|---|
| Remote control peer | 200 most-recent devices in a `<select>` | Searched, online first |
| User group (create, edit, bulk bar) | Every group in scope | Searched |
| Admin role scoped groups | Every group in the deployment | Searched, as chips |
| Group "can access" | Every group in scope | Searched, as chips |
| Device group "accessible by" | Every group in scope | Searched, as chips |

Fixed lists — statuses, enum choices, quality presets — stay plain `<select>`s. A combobox for four
options is worse, and the rule in `CLAUDE.md` says so explicitly.

### Multi-value selection

The existing combobox was single-value, which is why three pickers had stayed as multi-selects. It
now supports multiple selections as removable chips, with `Backspace` on an empty box removing the
last one.

The component emits **whichever shape the form already posted** — a comma-joined hidden field, or
one hidden input per value under an array name — so no controller, request validation or database
write changed. That was the point: a conversion that alters the request shape is a conversion that
can silently save the wrong thing.

Chips use the existing design tokens; no new colours were introduced.

## Fixed

### The admin role scope picker showed every group in the deployment

It ran an unscoped query, so a delegate confined to a single group could read the names of every
group in the deployment from the role form. Group names are not the most sensitive thing in the
system, but a scope boundary that leaks the shape of what is outside it is still a leak. It now
goes through `AdminScopeService` like every other group query.

### A dead query on every device-index page load

Every visit fetched every in-scope user, ordered them by name, and rendered none of them: the owner
picker had been converted to a combobox and the query was left behind. On a large deployment it was
the single biggest unbounded fetch on the page.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

Nothing else. No migration, no configuration change, and no request or API shape changed.

## Verification

- **677 PHP tests**, including five new ones covering the conversion: that the forms no longer
  render the whole directory, that the scope picker still submits its array, that an edit form shows
  the current selection as chips, that the joined-field pickers keep their field, and that the group
  search is scoped and capped.
- 253 web-client unit tests and 15 browser tests.
- The multi-value combobox was exercised in a real browser against a running image: searching,
  selecting, refusing a duplicate, removing a chip, and submitting — with the saved row checked in
  the database afterwards to confirm the round trip.
