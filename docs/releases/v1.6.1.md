# RD-API-Server v1.6.1

**Release date:** 2026-08-17

**Status:** Patch release. Four fixes to the browser remote desktop, plus documentation. No
breaking changes, no migration, no configuration change.

---

## You can see your pointer again

Reported from a live deployment: *"I don't see a mouse at all while trying to control, but the
mouse does work if I click."*

The viewer hid the local pointer unconditionally, on the assumption that the peer's cursor would
replace it. Two things were wrong with that.

The peer **suppresses cursor-position updates toward whoever is sending input** — deliberately, so
that a native client's own pointer does not fight with an echoed one. A browser viewer that has
also hidden its local pointer is then left with a remote pointer that lags or stops moving
entirely, and nothing to aim with.

And the peer sends no cursor at all unless asked. A native client draws its own local pointer over
the window, so the host has no reason to.

Both are fixed:

| Mode | Local pointer | Why |
|---|---|---|
| Controlling | Always visible | It is the one that tracks your hand |
| Watching, remote cursor present | Hidden | The remote pointer is the interesting one, and two are noise |
| Watching, no remote cursor | Visible | Better than none |

The viewer now also requests the peer's cursor at login, so a remote pointer exists to show.

## A connection in progress can be cancelled

Connecting to a machine that asks its user to accept left the viewer waiting with no way out.
Disconnect lives in the toolbar, and the toolbar is only rendered once a session is established —
so during rendezvous, relay, handshake and login there was no control at all.

A **Cancel** button now appears for the duration of the negotiation. A deliberate cancel is not
retried: closing the socket surfaces as a transport failure, which the reconnect policy would
otherwise treat as a transient drop and reconnect, turning Cancel into a pause.

## A configured WebSocket endpoint is validated

Reported from a second deployment:

```
The browser refused the URL: Failed to construct 'WebSocket':
The URL's scheme must be either 'http', 'https', 'ws', or 'wss'.
'rustdesk-hbbs' is not allowed.
```

`RUSTDESK_WS_ID_URL=rustdesk-hbbs:21118` is an **upstream** pasted into the **browser-facing**
setting. The browser is on someone's laptop; it cannot resolve a container name, and without a
scheme it will not even construct the socket.

Worse, the diagnostics page reported a healthy deployment, because it only checked the value was
non-empty. It now reports the specific mistake and names the setting to use instead. Unusable
values are no longer handed to the browser at all, so a deployment whose upstreams are correct
keeps working despite a leftover variable.

## A monitor change no longer blanks the session header

`peer_info` is re-delivered when the peer's display topology changes — docking a laptop, waking a
second monitor — and that copy carries the display list without the identity fields. Writing it
straight to the header turned a working session into `peer@undefined · undefined` some minutes in,
which reads like a fault rather than a monitor being plugged in.

## Documentation

The two WebSocket variable pairs are the most common setup mistake, so they are now explained
wherever an operator meets them:

| | Who dials it | What goes in it |
|---|---|---|
| `RUSTDESK_WS_*_UPSTREAM` | This container, over the Docker network | `rustdesk-hbbs:21118` |
| `RUSTDESK_WS_*_URL` | The operator's browser, over the internet | `wss://host/ws/id` |

- A table and explanation in the README.
- At length in `.env.example`, as two labelled options with the trade-off of each.
- Inline where the settings appear in the Compose examples.

**[examples/simple.docker-compose.yml](../../examples/simple.docker-compose.yml)** is new: the
whole stack in one file, no `.env`, nothing optional. Change four passwords and two hostnames and
it runs. The full-stack example keeps the pinned digests and hardening notes, and `.env.example`
remains the complete reference for everything that has a default.

```bash
docker compose pull && docker compose up -d
```

Nothing else.

## Verification

- 699 PHP tests, 254 web-client unit tests, **17 browser tests**, Pint and PHPStan.
- The cancel control and the cursor rule are covered in real Chromium, including that a cancelled
  attempt stays cancelled rather than reconnecting.
- Both viewer fixes were checked against a live peer.

**Noted while verifying:** the peer used for testing was sending a cursor but no video, which
initially looked like a regression. Running the previous release against the same peer at the same
moment showed identical behaviour, so it is that machine's state — an idle desktop sends no frames
until something changes — and not a change in this release.
