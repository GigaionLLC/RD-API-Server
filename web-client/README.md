# web-client

A browser-based RustDesk viewer, written from scratch. Connects to **stock** `hbbs` and
`hbbr` over WebSocket with **no server-side component of its own** — no bridge, no proxy,
no daemon.

Native ES modules. **No build step, no bundler, no code generation.** The files in `src/`
are the files that ship.

```
src/ + vendor/   →   copy anywhere and serve   →   done
```

---

## Why it needs no sidecar

`hbbs` binds `PORT+2` (21118) and `hbbr` binds `PORT+2` (21119) for WebSocket in every
stock build since server **1.1.6**. The bind is unconditional; a failure aborts startup.

`hbbr` also translates framing for mixed WebSocket/TCP pairs, so a browser receives **one
complete protobuf message per binary frame** and never has to implement the TCP
length-prefix codec at all.

## Status

| Area | State |
|---|---|
| Rendezvous, relay, NaCl handshake, password login | working |
| Video — VP8 / VP9 / AV1 / H.264 / H.265 via WebCodecs | working |
| Multi-monitor enumeration and switching | working |
| Cursor shapes, caching, position | working |
| Audio — Opus via AudioDecoder + AudioWorklet | working |
| Mouse, keyboard, wheel, drag, keyboard lock | working |
| Image-quality control | working |
| Clipboard — text and HTML, both directions | working |
| Chat — message the person at the remote machine | working |
| Auto-reconnect with backoff, human error messages | working |
| File transfer, terminal, 2FA login | not implemented |

Deliberately out of scope, : **cliprdr** (no web API can act as
a deferred OS clipboard file provider), **switch-sides** (needs input injection),
**port-forward** (a browser has no listening socket), **direct P2P** and **LAN discovery**
(browser limits — every session is relayed).

---

## Requirements

- **Chrome / Chromium, desktop.** Firefox and Safari are not supported; no touch, no
  mobile layout. One engine, no degraded modes.
- **A secure context** — HTTPS, or `localhost`. WebCodecs is unavailable otherwise, and
  there is no fallback tier by design.
- rustdesk-server **≥ 1.1.6**.

## Use it

Standalone, for development:

```bash
node tools/serve.mjs            # http://localhost:8788
```

Embedded — provide `window.RD_CONFIG` before loading `src/ui/viewer.js` and the connection
form is replaced by injected settings:

```html
<script>
  window.RD_CONFIG = {
    host: 'id.example.com',
    peerId: '123456789',
    serverKey: '<base64 ed25519 public key>',
    rendezvousUrl: 'wss://example.com/ws/id',     // required from an https page
    relayUrl:      'wss://example.com/ws/relay',
  };
</script>
<script type="module" src="/assets/webclient/ui/viewer.js"></script>
```

As a library, without the bundled UI:

```js
import { RustDeskSession } from './src/session/machine.js';

const session = new RustDeskSession({ host, peerId, serverKey, password });
session.onVideoFrame = (f) => { /* {display, codec, units, key} */ };
await session.connect();
```

`RustDeskSession` has **no method that sends input**. Input lives in `src/input/` and must
be wired deliberately, so holding a session is not enough to move a remote pointer.

## Layout

```
src/protocol/   wire codec + message descriptors (hand-written, no protoc)
src/crypto/     Ed25519 chain, X25519 box, secretbox stream, password derivation
src/transport/  WebSocket framing
src/session/    connection state machine, permissions, worker facade
src/media/      codec negotiation, video decode, audio, frame queue
src/render/     canvas surface, cursor overlay
src/input/      mouse, keyboard, DOM binding
src/workers/    the session, off the main thread
src/ui/         viewer
vendor/         tweetnacl, fzstd — pinned, checksummed, regenerated by scripts/vendor.mjs
docs/spec/      the wire specification this is implemented from
```

## Architecture

The whole session runs in a **worker**: socket, decryption, protobuf decoding, video
decode and compositing. Both canvases are transferred with `transferControlToOffscreen`,
so no frame byte reaches the main thread.

Measured against a live peer, main-thread cost per video frame:

| | |
|---|---|
| main thread | 0.574 ms/frame (composite 12.1 ms of 13.2 ms) |
| worker | 0 ms |

Audio stays on the main thread because `AudioContext` and `AudioWorklet` are unavailable to
workers. Input encoding stays there because it is cheap and belongs next to the DOM events
it reads.

Note that WebCodecs decodes off-thread in **both** modes — `decode()` only enqueues. What
the worker actually removes is compositing, decryption and protobuf decoding, all of which
scale with resolution and bitrate.

## Tests

```bash
npm test           # node --test, no browser needed
npm run test:browser  # Playwright, real Chromium
npm run typecheck  # tsc --noEmit --checkJs (JSDoc types, zero build output)
```

253 conformance tests over the protocol, crypto, session, input and clipboard layers. They encode the
protocol's silent-failure modes: pre-incremented secretbox counters, the `<= 1` byte
passthrough rule, per-field zigzag, packed vs unpacked repeated fields, negatively
signalled permissions, and the mouse mask requiring exactly one button bit.

The browser suite covers what Node cannot: real WebCodecs, canvas compositing,
`AudioContext`/`AudioWorklet`, and the module worker. It encodes a frame with a real
`VideoEncoder`, pushes it through the decoder, and asserts the pixels land — and that
every `VideoFrame` is released, since leaking them exhausts a small GPU pool and stalls
decoding permanently.

```bash
docker run --rm -v "$PWD:/app" -w /app mcr.microsoft.com/playwright:v1.48.0-jammy   bash -lc "npm i --no-save @playwright/test@1.48.0 && npx playwright test"
```

Live integration tools, which need a real peer:

```bash
node tools/integration/rendezvous.mjs --host H --peer ID --key K
node tools/integration/login.mjs      --host H --peer ID --key K --password P
```

## Provenance

This is an **independent implementation of a wire protocol**, written from the
specification in `docs/spec/` — message names, field names, tag numbers, state machines.

Concretely:

- **No source code, `.proto` file, or asset from any other implementation is present in
  this folder**, and none was copied or adapted at any point.
- The protobuf codec is **hand-written from the field tables** in `docs/spec/06-schema.md`,
  not generated from a third-party schema file. That is also why the viewer runs under a
  strict CSP with no `'unsafe-eval'`.
- Every runtime dependency is vendored from a pinned public package with its licence
  alongside it, regenerated by `scripts/vendor.mjs --check`.

To be precise rather than flattering about what "clean room" means here: the specification
was produced by analysing the **publicly documented and observable behaviour** of the
protocol, and the implementation was then written against that specification. Interoperating
with an existing protocol necessarily requires knowing what it is. What the process
guarantees is that the code is ours; it is not a claim that the protocol was invented
independently.
